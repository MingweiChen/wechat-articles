# Codex 终于有了「自己的工位」：OpenAI 买下 Ona 这件事，比看上去的要深

Gitpod 在 2025 年 9 月改名叫 Ona 的那一刻，其实就是为 6 月 12 日这场收购准备的。

只是当时没几个人看出来。

那时候的解读大多是：一家做云端开发环境的德国创业公司，转型去做 AI Agent 的安全执行平台，名字也换了，看着像是又一个被 AI 浪潮裹挟着改方向的中型 SaaS。直到这周四 OpenAI 公告把 Ona 收编，所有线索才连成一条线。

收购金额没披露。但配合着另一条新闻看，份量就出来了：6 月 8 日，OpenAI 刚刚秘密递交 IPO 文件，估值约 8520 亿美元。一边走 IPO 程序，一边花钱买基础设施，这种节奏说明，Ona 不是可有可无的补强，是必须在上市前合龙的拼图。

## 这是一笔「执行环境」的收购，不是「人」的收购

过去一年里，AI 公司之间的收购几乎都是奔着团队和模型去的：挖几个核心研究员、买一段权重、收编一个产品线。

Ona 这笔不太一样。

OpenAI 想要的是 Ona 那套**云端隔离的、可长时间运行的开发沙箱**。Gitpod 时代，这套东西卖给程序员：你打开浏览器就有一个完整的 Linux 工作台，IDE、终端、Git 都已经装好。改名 Ona 之后，它把同一套底座搬给 AI Agent 用。区别是 Agent 不下班，会在夜里继续跑测试、提 PR、改 bug，而沙箱本身要保证它跑出来的代码不会污染外网，也不会拖垮邻居的容器。

> Codex 一直缺的不是「能不能写代码」，而是「写完之后在哪里跑、能不能跑一整夜」。

这是这次收购最值得说的判断。Codex 周活刚刚突破 500 万，年增 400%。但只要它还跑在用户本地，它就受限于一件最朴素的事：人要关笔记本去睡觉。

Ona 解决的就是这个问题。它给 Codex 加了一个「永远开着的工位」——人下线了，Agent 还在云上的那台沙箱里继续干活，跑完了再把 PR 推回 GitHub。

## 把 Gitpod → Ona → OpenAI 这条 5 年弧线拉直来看

把时间往回拨。

Gitpod 2018 年在德国基尔起家，做的是「在浏览器里打开任意 GitHub 仓库」。那个年代它的客户画像是：两万块的笔记本带不动 Chromium 编译，索性把开发环境扔到云上，本地变成纯前端。这是给「人」用的云端工位。

到 2023 年大模型起来之后，一个细节开始浮现：Copilot 这种「补全式」Agent 还能跑在 IDE 里，但下一代的「自主式」Agent 要做的事情更重，比如查代码库、跑单测、改多个文件、自我验证。塞回本地 IDE 已经吃不消了。

于是 Gitpod 在 2025 年 9 月做了一件挺大胆的事：把名字、品牌、核心叙事整个换掉，从「程序员的云端 IDE」转向「AI Agent 的安全执行平台」。当时这事在国内开发者圈没什么水花，但在硅谷的 infra 圈是被议论过一阵的。它等于第一个把「Agent 是新一代用户」当成产品定义来写的公司。

转型之后 9 个月，被 OpenAI 收了。

按这条线推下去，故事其实很顺：先服务程序员把环境搬上云（2018-2024），再服务 AI 把环境给 Agent 用（2025），最后被全世界跑得最快的 Agent 大户买走（2026）。每一步都没拐弯，每一步都比上一步对了一点。

最让我好奇的是 Ona 自己工程团队的数据：他们家**Agent co-author 了 60% 的合并 PR，写了 72% 的代码行**，单团队吞吐量比改名前涨了 4 倍。这意味着他们不是在「卖工具给别人」，而是已经在自己用这套基础设施跑出超线性产出。一个团队的工程产能，不再正比于工程师人头。

OpenAI 看上的，应该正是这件事。

## 接下来要重写的，是云厂商的计费模式

把镜头拉远一点。

过去十年，云厂商的钱是靠「人买虚拟机」赚的。AWS、Azure、GCP 的 EC2 / VM 实例，定价模型背后假设了一个用户画像：人类工程师在工作日开机、下班关机、周末空转。所有的 Reserved Instance、Spot、Auto-scaling 优惠，本质都在围绕「人的工作节律」打折。

Ona 这种「Agent 工位」一旦铺开，这个假设就要塌一块。

Agent 不睡觉，没有早高峰晚高峰，也没有周五下午摸鱼。它跑起来的负载是 24/7、burst-y、按任务粒度结束。计费的合理颗粒度也不再是「实例小时数」，而是「Agent 完成任务花了多少 CPU·秒、读了多少行代码、调用了多少次模型」。

> 以前云厂商赚的是人买虚拟机的钱，未来云厂商赚的是 AI Agent 租虚拟机的钱。中间这条曲线，会让 IaaS 巨头都得重新写定价表。

这件事其实不是 OpenAI 一家在押注。同一个月里，Anthropic 也补了相邻的两块：收编了 Bun（一种 JavaScript 运行时）和 Stainless（约 3 亿美元，做 SDK 自动生成）。两家公司同月同方向地补「Agent 基础设施」，行业共识其实已经形成：**未来一年，AI 公司比拼的不只是模型，更是 Agent 在外部世界的「手脚」够不够长**。

## 还有一件更安静的事在发生

一个容易被忽略的数据：OpenAI 公告里提到，Codex 用户里**已经有 1/5 不是程序员，而是知识工作者**，比如分析师、产品经理、市场运营、写报告的人。而这部分非程序员的涌入速度，是开发者的 3 倍多。

这反过来表明一件事：「写代码」正在脱离「程序员」这个职业身份，变成一种通用的执行接口。

让一个产品经理用 Codex 跑一段 SQL、生成一份周报、改个内部小工具，这件事在 2024 年还需要他先学会 Python；2026 年只需要他能描述清楚要什么。Ona 在背后承担的是：不论这个人开没开电脑，那段任务都能在云上一个干净的沙箱里跑完，跑完了把结果推回他的飞书或者 Slack。

那么问题就来了：当一家公司里 80% 的「非工程岗」每天都能让 Agent 在云上替自己干一段重复的活，**SaaS 厂商卖的还应该是「软件席位」吗？**

软件公司过去 20 年的生意模型，是一份 license 卖给一个人。那是因为软件需要一个「用户」坐在屏幕前面操作。但如果未来真正在屏幕前面操作的是 Agent，软件就得换一种卖法：按调用次数、按任务完成、按 Agent 工时。

这事比 Codex 多 500 万周活更值得盯。

## 一句话定这次收购

OpenAI 买 Ona，表面看是又一笔工具补强，往深里看是给 500 万 Codex 用户外加 IPO 故事，配齐了一块叫「执行持久性」的基础设施。

而 Gitpod 在 2018 年挖下的这口井，2025 年改名时埋下的伏笔，2026 年被这场收购收尾——这条 5 年弧线本身，就是这件事最好的注脚。

明年这个时候再回头看，我猜会有一句更直白的总结：从 2026 年起，云厂商的客户里，**第一次真正出现了不是人的那一类**。
