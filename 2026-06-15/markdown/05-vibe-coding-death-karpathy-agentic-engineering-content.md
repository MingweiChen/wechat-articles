# Vibe Coding 一周年祭：14 个月生命周期，连 Karpathy 自己都不用它了

## 一个词的葬礼

我第一次认真使用「Vibe coding」这个说法，是 2025 年 3 月的一个深夜，做一个跨境电商的客户工单分析后台。

那天我没写一行代码，全程对着 Cursor 嘟囔需求，看它一边猜我的意思一边产出结果。两小时后我把链接发给客户，对方第二天回复说「能用，挺好」。我合上电脑那一刻有一种很奇怪的感觉，既不是「我做了一件了不起的事」，也不是「我偷懒了」，而是一种说不清的、轻飘飘的兴奋。后来我才知道，那种状态有个名字，叫 vibe coding，是 Karpathy 当年 2 月在推特上随手发明的。

一个词从诞生到全球流行，再到被发明者亲自宣判过时，整整 14 个月。

上周 Forbes 那篇标题《Is Vibe Coding Already Dead? Even Karpathy Is Moving On》落地的时候，我第一反应不是惊讶，而是想笑：连提出这个词的人都不再用它了，那它确实死了。Karpathy 给出的替代词叫 agentic engineering，同样还是他随口一发。

## 12 个月，从神坛到墓碑

为了写这篇，我把这一年多 vibe coding 的轨迹简单理了一下，发现它的生命曲线短得令人发指。

2025 年 2 月，Karpathy 在推特上写下这个词，本意是描述一种「不看代码、只跟 AI 聊感觉」的开发方式。当时 Cursor 刚刚 PMF，Lovable 还在内测，Replit Agent 没几个人知道。这条推文在中文圈传开后大概用了三周，就被翻译成「氛围编程」，开始进各种公众号文章的标题。

接着是 2025 年 4-9 月的全民狂欢期。投资人把 vibe coding 写进 deck，产品经理拿它解释为什么不需要工程师，独立开发者用它一周一个 SaaS 上线。Cursor 估值从年初的几亿美元一路冲到接近 100 亿，Replit 的 Agent 流水翻了 12 倍，Lovable 在欧洲一度成了创业者最先打开的那个网页。这段时间所有的故事讲法都一样：一个不懂代码的人，靠 vibe 也能做出能跑的东西。

到 2025 年底情况开始变。Cursor 团队一篇博客里悄悄改了说法，把产品定位从「AI pair programmer」改成「agentic IDE」。Replit Agent 升级到 v3 那一版，文档里出现一句话：「适合需要长期任务规划的专业开发者」。这两个细节当时没多少人注意，但回头看，它们就是讣告的前几行。

然后是 2026 年 2 月，Karpathy 自己在播客里说了一句：「Vibe coding 这个词已经过时了，现在更像是 agentic engineering。」

12 个月，从神坛到墓碑。

## 为什么是 14 个月，而不是 7 年

我个人对这件事最大的兴趣，不在 Karpathy 又造了一个新词，而在「14 个月」这个数字本身。

我做内容这几年，看着「O2O」用了 7 年才慢慢从主流叙事里消失，看着「Web 2.0」从 2005 年喊到 2012 年都还有人当回事，看着「大数据」从 2012 一路喊到 2018，「Mobile First」、「Cloud Native」也都是接近十年的生命周期。这些词代表的不只是技术，而是一整代人的工作方式和谈资。

vibe coding 是我亲眼见过的、生命周期最短的产业级概念。

为什么这一波这么短？我自己琢磨了一阵子，觉得不是 AI 词汇特别短命，而是——**工具的迭代速度，第一次超过了人类抽象总结的速度**。

O2O 那个年代，从「滴滴打车 1.0」到「美团点评打通线下」，工具迭代以年为单位，社会有充分时间消化、命名、争论、立派别。今天不是这样。从 Cursor 的「补全」到 Composer 的「文件级」，再到 background agent 的「我闭眼睡一觉它把整个 PR 提了」，整个跃迁只花了 8 个月。在这种速度下，一个词刚被广泛接受，工具的能力已经跑到下一站，词就被现实甩在身后。

按这个逻辑往下推，agentic engineering 大概率也活不过 12 个月。等到 AI agent 自主完成需求拆解、设计、测试、部署、维护的时候，「engineering」这个词本身都会显得碍事，因为已经不再是人在做工程了。

我赌 6-9 个月，业内会冒出下一个新词。不是 Karpathy 提，就是 Anthropic 的某个 PM 在博客里随手扔。

## 一个被埋葬的词，到底失去了什么

我写到这里突然停了一下，问自己一个问题：vibe coding 死了，那到底什么死了？

死的不是工具。Cursor 还活着，Lovable 还活着，Replit Agent 还活着，v0 和 Bolt 也都还在，而且大部分公司活得比一年前更好。死的也不是「不看代码就让 AI 写」这种工作方式，它没死，只是被收编进了一个更大的范畴里。死的，其实只是这个词本身指向的那个**心态**：

> 一种「我不需要懂技术细节、我只需要表达感觉、AI 会帮我把感觉翻译成产品」的轻盈感。

这个心态，在 2025 年 3 月我那个深夜里是真实存在的。我那晚不需要懂数据库索引、不需要懂前端打包、不需要懂 API 鉴权，只需要把「我想要什么」说清楚。**这是 vibe 的本质，它不是一种技术，是一种姿态**。

但到了 2026 年的今天，这种姿态已经走不通了。Cursor 的 background agent、Claude Code、Codex 这一批新工具，要求你做的事情更像项目经理，而不是 vibe 玩家：你得给 agent 写规格书，得审 plan，得 review diff，得在 agent 卡住时候介入调试。它仍然比手写代码省力，但「凭感觉」三个字已经撑不起来了。

vibe coding 死的，是它名字里的那个「vibe」。

剩下的活着的部分，更接近一种**工业化的人机协作**：人来定义问题、定义验收、做最后判断；AI 完成绝大多数中间步骤。这件事配得上一个更冷静的名字，叫 agentic engineering 也好，叫 AI-native development 也好，反正不再是「凭感觉」。

## Karpathy 跳槽 Anthropic，和这件事的因果关系

我注意到一个细节，国内媒体很少有人提：Karpathy 是 2026 年 5 月正式入职 Anthropic 的，方向是预训练。

这个时间点，距离他亲手「埋葬 vibe coding」只有 3 个月。

把这两件事放在一起看，逻辑就出来了。Karpathy 过去几年承担了一个非常特殊的角色，是 AI 时代的「面向大众的概念翻译器」。从「Software 2.0」到「Tokens are the new bytes」，再到 vibe coding，他擅长的事情是**把工程师圈子里的事，翻译成普通人也能传播的话**。

但当一个人决定回到预训练这种最底层、最不需要面向大众的工作时，他就不再需要继续生产「面向大众的词汇」了。所以他亲手把 vibe coding 翻篇，提出 agentic engineering，前者是产品时代的词，后者是回归技术圈内部的词。这不是巧合，是一次很自然的角色切换。

我顺着这条线再推一步：当行业里最擅长造「翻译词」的人选择回到底座，意味着 AI 编程的「大众消费品时代」可能也走到了一个阶段尾声。接下来真正决定走向的，不再是 Karpathy 这种「布道者」，而是 Anthropic、OpenAI 内部那些埋头做 RLHF、做 long-horizon agent 的研究员。他们不会再造像 vibe coding 这么轻盈的词，他们造的词会更技术、更冷、更不适合在朋友圈传播。

## 作为一个用过它的人

我不打算给这件事下「时代里程碑」之类的判断，那是套话。

我只想说一件具体的事：作为一个真的在 2025 年用过 vibe coding 工作流的人，我自己的工作方式确实变了。我现在写代码时已经不再「凭感觉」，而是先打开 Linear 写 spec，再用 Claude Code 起一个 plan，看 plan 里有没有遗漏边界条件，然后让 agent 跑，跑完我自己 review、提问、改。这套流程比 14 个月前麻烦了一点，但出来的东西也比当年靠 vibe 拼出来的稳得多。

某种意义上，**我自己就是 vibe coding 死亡的一份证据**。它教会了我一件事——AI 可以替我写代码——然后悄悄离开，把我推向一种更慢、但更可控的协作方式。

这个词的葬礼很短，14 个月。但它留下来的影响，比它存活的时间长得多。
