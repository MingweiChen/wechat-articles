如果说 2024 年是 Cursor/Copilot 把 AI 写进 IDE 的一年，2025 年是 Claude Skills、Agent Skills 概念冒头的一年，那 2026 年的现在，技能化正在变成 AI 协作的新基础设施。

最值得玩味的是 mvanhorn/last30days-skill。它的定位非常具体：一个 AI Agent 技能包，专门干一件事，把任何主题在 Reddit、X、YouTube、Hacker News、Polymarket 和公开网络上"全网拉一遍最近 30 天的真实声音"。

一句话总结：开发者们不再写"工具"，他们在写"能力"。

02 从 Cursor 到 Skill，AI 协作的范式正在第三次跃迁

回头看 AI 协作工具的演化，三段路径已经很清楚：

第一段（2022-2023）：Copilot 时代。 AI 是补全引擎，给你写代码下一行、下一段。人是主角，AI 是助手。

第二段（2024-2025）：Cursor / Agent 时代。 AI 是执行体，能多文件改动、能跨步骤推理。但每个 Agent 还是一个"一体化系统"：内置的工具、内置的提示词、内置的工作流，换个场景就要换个产品。

第三段（2026 进行时）：Skill 时代。 通用 Agent + 可装载的技能包。同一个 Claude、同一个 GPT，今天装上 last30days-skill 就是研究员，明天装上 pm-skills 就是产品经理，后天装上 taste-skill 就是设计 reviewer。

这件事的本质和当年 npm 出现时一模一样。在 npm 之前，写 JavaScript 项目要么自己造轮子，要么把别人 GitHub 上的代码 copy 进来魔改。npm 出现后，npm install 一行命令，几百万开发者写的能力就接入了你的项目。

Skill 在做的事，是把"能力复用"从代码层抬升到 Agent 层。

苹果这周也下场了。apple/container 一周 +990 Star，开源了自己的容器引擎。背后的逻辑一脉相承：标准化的封装单位，意味着可分发、可组合、可商业化。先有 Docker 把"环境"标准化，现在有 Skill 把"能力"标准化。

OpenAI 的 openai/plugins 仓库本周也悄悄涨了 340 Star。这个项目的存在本身就很说明问题：连最不喜欢开放的 OpenAI，都开始在 Plugin/Skill 这个方向上下注。

03 SKILL.md 凭什么成为 AI 时代的新接口

技术上看，一个 Skill 包简单得有点过分。核心就是一份 SKILL.md 文件，里面写清楚三件事：

• 这个技能是干什么的（description）

• 什么时候应该被调用（when to use）

• 执行步骤和工具调用（procedure）

加上一两个 Python/Shell 脚本、几个示例文件，整个包就齐了。Agent 在运行时扫一下这个 SKILL.md，按需加载，按需执行。

为什么这套东西能起来？三个理由：

第一，它解决了"通用模型不够专"的核心矛盾。 GPT-5、Claude 4.5 这种通用大模型，写代码、写文案都还行，但让它做你公司专属的 PRD 模板？让它按你团队的 code review 标准打分？让它用你研发部门的术语写周报？通用能力到不了那一层。Skill 把"领域 know-how"打包，恰好填上了这个缝。

第二，它和现有 Agent 生态完全兼容。 Claude Skills、Cursor Rules、各种 Agent 框架，本质上都在向同一个方向收敛：一个声明式的 markdown 文件 + 一组可执行脚本。开发者不需要学新语言、不需要绑定特定平台。

第三，它的分发成本接近零。 Skill 本质上就是一个 GitHub 仓库，clone 下来扔进 ~/.skills/ 目录或者推到任何兼容的 Agent 平台，立即可用。这个分发链路比 App Store、比 Chrome 扩展商店、比 PyPI 都更轻。

这意味着：每一个开发者、每一家公司、每一个岗位，都可以把自己积累的 know-how 封装成一份 SKILL.md，让通用 AI Agent 立即拥有这份专业能力。

04 Skill 是 AI 时代新货币，而我们正站在零号通胀点

回到那张本周 Trending 截图。chopratejas/headroom、Panniantong/Agent-Reach 这些项目名字看起来非常普通，但都在做同一件事，把某种特定能力（人脉拓展、销售触达、研究检索）抽象成可复用的 Skill 包。

每一个这样的仓库，本质上都是一份"AI 时代的简历"。开发者不再说"我会写 Python"，而是说"我封装了一个能让任何 Agent 都会做用户访谈的 Skill"。技能本身可以被 fork、可以被 star、可以被组合、可以被定价。

如果再往前推一步：

当 Skill 成为标准化的能力单位，"会什么"就不再是个人简历上的形容词，而是一个可分发、可计量、可被 AI 直接调用的资产。

这是真正的范式转移。过去十年互联网讲"工具复用"，比如 SaaS、API、开源库；未来十年 AI 讲"能力复用"——Skill 包、Agent 模板、技能市场。前者卖的是软件，后者卖的是判断力、品味、专业经验。

lfnovo/open-notebook 这周新增 3371 Star，做的是开源版的 NotebookLM——把"研究、笔记、思考"这一整套知识工作流打包。它的火爆本身就是信号：当用户能用 Skill 把整个工作流接管，传统 SaaS 的护城河会被重新定义。

回到一个开发者最该问自己的问题：你下一个仓库的名字，会不会以 "-skill" 结尾？

如果答案是会，恭喜，你已经站在了下一波浪的起点。

05 写在最后

Skill 生态集体爆火的这一周，回头看会是一个标记性的时间点。

Cursor 让 AI 学会写代码，Skill 让 AI 学会做事；Copilot 解决了"怎么写"，Skill 解决了"做什么"。

通用模型负责底层智能，Skill 负责领域知识。这是一个标准的"基础设施 + 应用"的双层结构，互联网走过这条路，移动端走过这条路，云原生走过这条路。AI 这一波，轮到了 Skill。

GitHub Trending 这周用 Star 数告诉所有人：游戏规则已经在变了。能不能上车，不取决于你写不写得动模型，取决于你愿不愿意把自己最值钱的那部分经验，写成一份 SKILL.md。

共勉。
