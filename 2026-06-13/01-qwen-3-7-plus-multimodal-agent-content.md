## 01 三件套登场：看屏幕、写代码、操作 GUI

Qwen3.7-Plus 不是单一模型升级，而是把多模态 Agent 拆成三个独立能力包。

| 能力名 | 输入 | 输出 | 典型场景 |
|---|---|---|---|
| **Visual Agent** | 屏幕截图、相机帧 | 元素定位、操作意图 | 看懂网页、识别按钮、读表单 |
| **Visual Coding** | UI 截图、设计稿、视频 | HTML / CSS / JS / SVG / Draw.io | 截屏一键还原网页 |
| **GUI Agent** | 自然语言任务 | 屏幕点击、键盘输入、滚动 | 自动操作浏览器、桌面应用 |

> 这三件套不是孤立模块，是一个完整的「感知 → 思考 → 行动」闭环。

过去做多模态，模型只能告诉你「这张图里有什么」。

Qwen3.7-Plus 这一版能告诉你「这张图里我下一步该点哪」，并且把这个点击动作真的发出去。

阿里官方在发布会上演示了一段：一个用户用自然语言说「帮我把购物车里的所有商品结算掉，地址用上次保存的，发票寄到公司邮箱」，模型自己截屏、定位购物车按钮、点击进入、勾选商品、跳转支付、填地址、选发票，全程没人介入。

> 这是多模态模型第一次在公开演示里完成一个完整的电商交易闭环。

整个流程跑了 42 秒，比人工操作还快。

中间出现了一次「优惠券自动弹窗」，模型识别出弹窗不是关键路径，直接关闭继续往下走，没被打断。

这种「会处理异常」的能力，过去 RPA 工具靠脚本异常处理，写一周都不一定覆盖全；现在模型靠视觉理解直接跳过。

## 02 ScreenSpot Pro 80.3 是个什么概念

跑分这块直接看数字。

| 模型 | ScreenSpot Pro | OSWorld-Verified |

| **Qwen3.7-Plus（阿里）** | 80.3 | 56.5 |

数据来源：阿里通义实验室 6 月 12 日发布材料，第三方 llm-stats 整理。

> ScreenSpot Pro 衡量的是模型能不能在高分辨率、专业场景下精准点中按钮。80.3 这个分意味着 100 次点击里有 80 次落到正确像素位置。

ScreenSpot Pro 的难度在哪？

这个基准用的是专业设计软件、IDE、视频剪辑工具的真实截图，分辨率 4K 起步，按钮密度极高。

人类用户面对 Photoshop 工具栏里那一排小图标，第一次用也要找半天。模型能在这种环境下做到 80% 命中率，意味着「专业软件自动化」第一次有了通用解。

OSWorld 更狠，直接把模型扔进真实的 Ubuntu 桌面，让它装软件、改配置、跑命令、处理报错。

测试任务包括：

- 在 LibreOffice 里做一份带图表的财务报表
- 在 GIMP 里抠图并保存为透明 PNG
- 在终端里配置 Nginx 反向代理
- 在 VSCode 里调试一段有 bug 的 Python 代码

> 56.5 在这个榜上属于第一梯队，半年前国产模型在这个榜上还是个位数。

OSWorld 的特点是任务完整闭环，模型不能只识别按钮，还得真把任务做完。中间任何一步出错都算失败。

> 跑分不是终点，但跑分是工业界第一个对齐的语言。当 ScreenSpot Pro 和 OSWorld 同时被刷到第一梯队，意味着「能跑通真实任务」从「PPT 上的能力」变成「API 里的能力」。

## 03 Visual Coding 怎么做到截屏即代码

Visual Coding 是这次三件套里最容易被低估的一块。

输入是一张图，输出是可运行的前端代码。

支持的输出格式包括：

- **HTML / CSS / JavaScript**：直接出可部署的网页
- **SVG**：把图标、Logo、信息图还原成矢量
- **Draw.io**：把架构图、流程图还原成可编辑的图表源文件
- **React 组件**：拆成符合工程规范的组件文件
- **Tailwind 配置**：自动识别样式并输出 Tailwind class

实际测试里，一张电商详情页截图扔进去，输出的 HTML 在浏览器里渲染出来，按钮位置、字体大小、间距、配色，整体复刻度肉眼难分辨。

> 这不是「看图说话」，这是「看图做事」。

Visual Coding 的工程价值在哪？

- **设计稿到代码的搬运工**：UI 设计师交付的 Figma 截图，前端不用一行行手写
- **竞品分析自动化**：把对手的官网截图扔进去，三秒拿到结构和样式
- **老系统迁移**：把老旧网页截图喂给模型，输出现代化的 HTML 重构版本
- **AI 应用快速搭建**：产品经理画一张草图，模型直接出可交互原型
- **图表反向解析**：PPT 里的柱状图，模型识别出数据后直接输出 ECharts 配置

阿里给的演示里有个细节：一张包含图表的 PPT 截图扔进去，模型不仅识别出柱状图的数据，还把 ECharts 的配置代码一并吐出来。

数据精度还原到原图的 95% 以上。

> 这意味着 PPT 反向工程从「人工对着图敲数」变成「截图 + 一次 API 调用」。

对内容生产者来说，这是一次「视觉到代码」的彻底拉平。

过去前端工程师的核心壁垒之一是「看图复刻」的速度，现在这个壁垒被模型抹平。

不是说前端会消失，而是「写样式」这件事不再是前端的主要工作，前端会更聚焦在交互逻辑、性能优化、工程化建设上。

## 04 GUI Agent 怎么让 AI 真的会用电脑

GUI Agent 这一块是真正改变交互范式的地方。

> 过去 AI 用电脑，靠的是 API 调用。现在 AI 用电脑，靠的是点鼠标和敲键盘。

Qwen3.7-Plus 的 GUI Agent 工作流程：

1. **截屏**：拿到当前屏幕的位图
2. **定位**：识别屏幕上所有可交互元素的位置和语义
3. **决策**：根据任务目标判断下一步该点哪、输什么
4. **执行**：发出鼠标坐标点击、键盘输入、滚动指令
5. **复盘**：截屏比对，看任务是否完成，没完成继续循环

这个闭环跑通的意义是：**任何有图形界面的软件，都可以被 AI 操作**。

不需要 API，不需要插件，不需要 SDK。只要这个软件有按钮，AI 就能点。

阿里官方放出来的实操案例覆盖：

- 自动登录企业 OA 系统、填写报销单、上传发票
- 自动打开淘宝、搜索商品、加购、下单
- 自动操作 Photoshop、调色、裁剪、导出
- 自动跑通 Excel 的复杂数据透视、生成图表
- 自动在飞书里建表格、拉公式、发周报

> 这意味着「重复性桌面工作」第一次有了通用解。RPA 行业过去十年都在做这件事，但 RPA 的脆弱性在于「界面一变就崩」。

多模态 Agent 不依赖固定坐标，靠视觉理解，对界面变化天然鲁棒。

具体差异：

| 对比维度 | 传统 RPA | GUI Agent |
|---|---|---|
| **定位方式** | 固定坐标 / DOM 路径 | 视觉理解 + 语义识别 |
| **界面改版** | 脚本失效要重写 | 自动适配 |
| **任务描述** | 拖拽流程图 / 写代码 | 自然语言一句话 |
| **异常处理** | 需要预先写 try/except | 模型自己判断跳过 |
| **跨软件协作** | 需要中间件桥接 | 直接跨应用切换 |
| **学习成本** | 需要专门培训 | 任何员工都能用 |

> 这张表的核心信息：GUI Agent 不是 RPA 的替代品，是 RPA 的下一代形态。

企业 IT 部门过去采购 RPA 工具的预算，未来会逐步迁移到多模态 Agent API。

## 05 实操场景对比：Visual Agent 落到哪些活儿

把三件套放在具体场景里，能力差异就清楚了。

| 场景 | 传统方案痛点 | Qwen3.7-Plus 方案 | 时间节省 |
|---|---|---|---|
| **电商详情页复刻** | 前端手写 HTML 8 小时 | 截屏 → Visual Coding → 微调 30 分钟 | 93% |
| **企业 OA 自动化** | RPA 脚本写一周，改版重写 | GUI Agent 用自然语言描述任务 | 80% |
| **架构图源文件还原** | 设计师手动重画 Draw.io 2 小时 | Visual Coding 直接吐 .drawio | 95% |
| **PPT 配图提取** | OCR + 手动整理 1 小时 | Visual Agent 一键提取 + 结构化 | 90% |
| **跨语言文档 OCR** | 多个 OCR 工具拼接，准确率低 | 一个模型搞定 30+ 语言 | 70% |
| **视频内容理解** | 抽帧 + 逐帧分析，几十分钟 | 原生 256K 上下文，一次看完 | 85% |

> 这张表的核心信息：从「写代码做自动化」变成「用自然语言做自动化」，门槛从程序员降到办公室任何一个员工。

值得注意的是 OCR 这块。

Qwen3.7-Plus 的 OCR 不再是单独训练的模块，而是和多模态推理融合在一起。识别完文字之后，模型直接理解上下文，包括识别罕见专业字符、低光照、模糊、倾斜文档。

医疗票据、古籍扫描、手写发票，这些过去 OCR 厂商攻不下的硬骨头，多模态大模型用「看 + 想」的组合拳直接掀桌。

> 单独 OCR 是「识别」，多模态 OCR 是「理解」。前者输出字符串，后者输出结构化业务数据。

实际跑过的案例：

- 一张挂号收据扫描件，模型识别后直接结构化成 JSON，字段包括科室、医生、金额、时间，准确率 99% 以上
- 一份手写的差旅报销凭证，模型自动归类到「交通费」「住宿费」「餐饮费」三档
- 一份扫描的古代医书，模型识别出繁体字后还能给出现代汉语译文

这种「识别 + 理解 + 转换」的一站式能力，过去要串接三到五个工具才能做到。

现在一个 API 调用搞定，还不用担心多个工具之间的格式转换出错。

这对财务、医疗、法务这些「纸质资料密集型」行业是一次生产力重塑。过去一个财务人员一天处理几百张票据算高效，未来在 Visual Agent 加持下，一上午就能跑完整个部门的报销堆。

## 06 256K 原生上下文 + 1M 扩展：视频任务的解锁键

多模态模型一直有个天花板：上下文。

文字模型早就跨过 100K 大关，但多模态因为视觉 token 消耗大，一直在 32K 到 64K 之间徘徊。

Qwen3.7-Plus 这次原生支持 256K 上下文，可扩展到 1M。

> 1M token 的视觉模型意味着什么？意味着可以一次性塞进一部两小时的电影，让模型完整理解情节、人物、场景切换。

具体能干嘛：

- **长视频问答**：上传一场 3 小时的发布会，问「张三在第几分钟提到了价格」，模型直接定位
- **多帧时序推理**：让模型看完一段监控视频，判断异常行为发生在哪一秒
- **PDF 长文档解析**：上百页带图表的研究报告，一次性解析完
- **代码仓库视觉化**：把整个项目的 UI 截图丢进去，模型理解全局架构
- **教学视频拆解**：上传一节 2 小时的 Python 教学视频，模型自动生成带时间戳的目录

阿里给的内部测试显示，在 1M token 长度下，关键信息召回率依然保持在 90% 以上。

> 这个数字过去只有文字模型能做到。多模态在 1M 长度下保持 90% 召回，是个工程奇迹。

长上下文对企业场景的意义：

- 法务一次性看完几百页合同附件
- 财务一次性核对全年报销凭证
- 客服一次性回顾客户所有历史会话视频
- 销售一次性分析整季度的客户访谈录像

> 长上下文 + 多模态 + Agent 行动，这三件事叠起来，才是「AI 员工」的真正形态。

阿里在长上下文这块用了一个叫「视觉 token 压缩」的技术，把同一段视频的连续帧在编码阶段做去冗余处理，单位时间消耗的 token 量降了 60% 以上。

这意味着同样的算力预算下，模型能看更长、看更细、看更清楚。

> 工程优化往往比模型架构创新更难推进，但在落地阶段更值钱。

企业客户最关心的从来不是「跑分多少」，而是「这个模型放进我的业务流里，成本和延迟能不能接受」。Qwen3.7-Plus 在这两个维度上都给出了正面答案。

## 07 阿里云百炼商用：API 一行起跑

发布技术不算什么，发布商用 API 才算落地。

百炼平台同步开放 Qwen3.7-Plus 的三个调用入口：

| API 模式 | 适用场景 | 计费方式 |
|---|---|---|
| **VL 模式** | 多模态对话、图像理解、OCR | 按 token 计费 |
| **Coding 模式** | 截屏转代码、设计稿还原 | 按 token + 输出字符数 |
| **Agent 模式** | GUI 自动化、桌面操作 | 按任务次数计费 |

> 三种模式可以独立调用，也可以组合编排。一个完整的「截屏 → 理解 → 写代码 → 执行点击」闭环，可以在一个 API 链路里完成。

百炼平台同时给出了主流 Agent 框架的适配文档：

- **LangChain**：直接以 Tool 形式接入
- **LlamaIndex**：作为多模态 Retrieval 节点
- **AutoGen**：作为 Vision Agent 角色
- **CrewAI**：作为多 Agent 协作中的视觉理解节点
- **Dify / FastGPT**：开箱即用的低代码集成

> 兼容性这件事看起来不性感，但它决定了一个模型能不能进生产。

海外开源框架的兼容支持，意味着海外开发者也能直接用上百炼的 API。

国际版的 Model Studio 同步上线，海外用户拿到的是同一个能力包，没有阉割版。

定价策略也比想象中激进：

- VL 模式：输入 1 元 / 百万 token，输出 4 元 / 百万 token
- Coding 模式：在 VL 基础上 +30%
- Agent 模式：单次任务 0.05 元起步，按操作步数累加

> 这个价位比 GPT-4 Vision 便宜 40% 以上，比 Claude 4.5 Sonnet 便宜 25%。在跑分领先的前提下，价格还更低，对开发者吸引力会很直接。

阿里这次明显是「能力 + 价格 + 生态」三管齐下，目的就是把海外开发者从 OpenAI、Anthropic 那边拉过来一部分。

## 08 国产 Agent 拐点：从「能演示」到「能干活」

把镜头拉远一点。

过去半年，硅谷在卷的是 Gemini Omni 这种「any-to-any」的统一多模态架构，谷歌 I/O 2026 发布的 Gemini Omni 把文本、音频、图像、视频做成单一输入输出管道，主打视频生成和对话式剪辑。

国内卷的是另一条路：**让模型真正会操作软件**。

| 维度 | Gemini Omni（谷歌） | Qwen3.7-Plus（阿里） |
|---|---|---|
| **核心定位** | 统一多模态创作 | 多模态 Agent 行动 |
| **主战场** | 视频生成、对话式编辑 | 屏幕理解、GUI 操作、代码生成 |
| **典型用户** | 创作者、内容生产者 | 开发者、企业自动化、办公场景 |
| **商用通道** | Google AI 订阅（Plus / Pro / Ultra） | 阿里云百炼 API（按量付费） |
| **生态接入** | Google Workspace、Android | LangChain / LlamaIndex / AutoGen / CrewAI |

> 两条路线没有谁对谁错，是两套问题定义。谷歌想做创作工具，阿里想做生产力工具。

国产 Agent 这一年走的路径很清晰：

- 2025 年上半年：堆参数、刷文本榜
- 2025 年下半年：多模态融合、做长上下文
- 2026 年上半年：把多模态能力变成 Agent 行动能力

这一波的关键不是「跑分超过谁」，而是「商用 API 能不能被开发者真用起来」。

百炼平台的国际版同步上线、对主流海外框架的兼容、按 token 和按任务的灵活计费，这三件事加起来，意味着 Qwen3.7-Plus 第一次进入了「全球开发者可触达」的状态。

> 当一个国产模型在 ScreenSpot Pro 和 OSWorld 同时刷到第一梯队、又把 API 开到主流 Agent 框架，这件事的意义已经超出了「中国模型追上来了」的叙事，而是「国产 Agent 正在重新定义生产力软件的交互层」。

下一阶段拼的是生态。

谁先跑出杀手级 GUI Agent 应用、谁先把企业级自动化场景啃下来、谁先在海外开发者社区拿到口碑，谁就在下一轮多模态竞争里占住身位。

> 国产 Agent 的拐点，从这次发布开始算。

操作系统的下一代交互层正在被重新定义。

过去三十年，人类用鼠标和键盘操作软件。

接下来三年，人类用自然语言下达任务，AI 用鼠标和键盘操作软件。

这个范式转移已经开始了。

短期内，受益最直接的是企业自动化场景：报销、报表、数据录入、客户服务、跨系统数据搬运。这些过去需要专门 IT 团队维护脚本的工作，未来用一个 Agent API 就能跑通。

中期看，受益的是个人办公效率。每个员工都有一个「数字分身」帮自己处理重复事务，把时间释放出来做创造性工作。
