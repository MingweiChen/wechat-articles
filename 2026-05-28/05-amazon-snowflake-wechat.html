Amazon 60亿美元押注 Snowflake：Agentic Computing 时代来了

60亿美元。

这是 Amazon 刚刚和 Snowflake 签下的合作金额，专注方向只有一个：**Agentic Computing Chips**。

继 Apple、Meta 之后，又一家万亿级巨头杀入 Agent 芯片赛道。三大科技巨头同一季度入局，这不是巧合，这是信号。

AI Agent 专用芯片的时代，来了。

---

01 为什么 AI Agent 需要专用芯片？

先搞清楚一个问题：现有的 GPU 不够用吗？

答案是：**不够，而且差得远。**

传统 GPU 是为训练设计的——把海量数据喂给模型，跑几十小时、几天、甚至几周，输出一个可用的权重文件。这个过程对延迟不敏感，对吞吐量极度敏感。

但 AI Agent 的工作模式完全不同。

一个典型的 Agent 任务是这样的：用户说"帮我订下周三飞上海的机票"，Agent 要做什么？

1. 理解意图，提取关键信息 2. 调用日历 API，检查日程冲突 3. 调用航班查询接口，获取候选航班 4. 根据历史偏好筛选 5. 生成确认对话 6. 等待用户反馈 7. 调用支付接口完成订票

7 个步骤，每一步都需要实时响应，每一步之间还有依赖关系。

这意味着：

  • **延迟敏感**：用户不会等你 5 秒钟才蹦出下一句话
  • **上下文频繁切换**：从 LLM 推理切到 API 调用再切回来
  • **多任务并行**：同时处理多个用户的多个 Agent
  • **状态管理复杂**：需要保持长对话的上下文

    • GPU 的架构是为批量处理设计的。让它做这种"碎片化、高频次、低延迟"的工作，就像用挖掘机挖花盆——能干，但浪费。

    Snowflake 的 CEO Sridhar Ramaswamy 在发布会上说了一句话很到位：

    > "训练像炼钢，推理像切菜。你不能用高炉切黄瓜。"

    这就是 Agentic Computing Chips 存在的理由：**专为 Agent 推理场景优化的芯片架构。**

    02 60亿美元背后：Amazon 的真实意图

    AWS 每年在芯片上的资本开支超过 200 亿美元。60 亿放在这个体量里，不算最大的单笔投入，但这笔钱的信号意义远超账面价值。

    第一，这是 Amazon 对自研芯片战略的一次重大调整。

    过去几年，AWS 主推两款自研芯片：Trainium（训练）和 Inferentia（推理）。但市场反馈一直不温不火。原因很简单——它们针对的是传统 AI 工作负载，而不是 Agent。

    这次和 Snowflake 合作，意味着 Amazon 开始认真对待 Agentic Computing 这个新品类。与其自己摸索，不如和有技术积累的玩家绑定。

    第二，这是对 Nvidia 的一次战略试探。

    目前 Nvidia 在 AI 芯片市场的份额超过 80%。但 Nvidia 的产品线同样针对训练和传统推理，对 Agent 场景的优化有限。

    如果 Agentic Computing Chips 能打开市场，Amazon 就有机会在下一代芯片战争中占据有利位置——不是正面硬刚 Nvidia 的存量市场，而是开辟一个新战场。

    第三，这是云计算巨头的卡位之战。

    看一组数据：

  • Apple 今年 3 月收购 Agent 芯片初创公司 Furiosa，交易金额未披露，业内估计超过 20 亿美元
  • Meta 4 月宣布 50 亿美元专项预算，用于 Agent 芯片研发
  • Google 持续加码 TPU v6，已经在内部测试 Agent 场景优化版本

    • 四大云巨头，三家已经明牌押注 Agent 芯片。

    Google 虽然没有单独披露 Agent 相关投资，但 TPU 团队的动向说明一切。

    剩下的问题不是"要不要做"，而是"谁先做出来"。

    03 Snowflake：为什么是它？

    可能有人会问：Snowflake 不是做数据仓库的吗？怎么突然做芯片了？

    这里有一段前史。

    2024 年，Snowflake 收购了一家叫 Gradient 的公司，专注低延迟推理架构。当时业内没太在意——一家数据公司收购一家小众芯片团队，能掀起多大浪？

    结果 Gradient 的团队在 Snowflake 内部闷声做了两年，拿出了一套完整的 Agentic Computing 架构。核心卖点有三个：

    1. **Sub-100ms 端到端延迟**：从接收请求到返回结果，全流程压到 100 毫秒以内 2. **上下文复用引擎**：多轮对话的上下文不用重复加载，省时省显存 3. **多 Agent 协调调度**：同一芯片上可以同时跑多个 Agent，互不干扰

    这三个特性，精准命中了 Agent 场景的痛点。

    Amazon 选择 Snowflake，不是因为它最大，而是因为它最快。技术领先 6-12 个月，在芯片行业就是代差。

    ---

    04 Agent 芯片：云计算的下一个战场

    回到更大的图景。

    过去十年，云计算的竞争核心是"算力"——谁的 GPU 多、谁的集群大、谁的训练成本低。这是一场军备竞赛，资本开支决定胜负。

    但 Agent 时代的竞争逻辑变了。

    Agent 对芯片的需求不是"大"，而是"快"和"聪明"。

    不是比谁能跑更大的模型，而是比谁能让用户的 Agent 响应更快、体验更丝滑、成本更低。

    这意味着：

  • **架构创新比堆资源重要**：专用芯片可以用更低的功耗实现更好的效果
  • **软硬件协同是关键**：芯片设计要和 Agent 框架深度绑定
  • **生态卡位价值巨大**：谁先定义 Agent 芯片的标准，谁就掌握下一代基础设施的入口

    • 从这个角度看，Amazon 和 Snowflake 的合作不仅仅是一笔采购——它是 AWS 对下一代云计算基础设施的一次押注。

    ---

    05 对开发者意味着什么？

    如果你是 AI 应用开发者，这件事和你直接相关。

    短期（6-12个月）

    ：暂时没有影响。Agentic Computing Chips 还在研发和测试阶段，不会马上上线。

    中期（1-2年）

    ：AWS 会推出针对 Agent 的新实例类型。如果你的业务是 Agent 密集型的（比如客服、助手、自动化流程），到时候迁移过去，成本可能降 30-50%，延迟可能降一个数量级。

    长期（3-5年）

    ：Agent 芯片会变成云计算的标配，就像今天的 GPU 一样。不用 Agent 芯片跑 Agent，就像今天不用 GPU 跑训练——能跑，但没人这么干。

    对开发者的建议很简单：**关注 AWS 的产品路线图，等第一批实例上线时做好迁移准备。** 现在不用焦虑，但也别完全不管。

    训练的红利期已经见顶。推理的战争才刚刚开始。

    而 Agentic Computing，就是下一个战场。
