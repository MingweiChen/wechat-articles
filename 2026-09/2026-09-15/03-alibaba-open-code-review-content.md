# 阿里开源Open Code Review：代码审查要从“人看Diff”变成“AI先过筛”了！

> AI写代码越多，最先工业化的不会是写代码，而是审代码。

## 先看事实

- GitGenius 2026-09-13：alibaba/open-code-review成为Repository of the Day，当日新增约748星，总星数约2.35万。
- GitHub README：该工具源自阿里内部AI代码审查助手，两年服务数万开发者，开源后支持Git diff、全文件扫描、多语言规则和多模型后端。
- Flowtivity 2026-09-12：其AACR-Bench显示同模型下Open Code Review precision为33.90%，Claude Code为7.23%，token消耗约为后者九分之一。

## 代码审查正在成为AI时代的瓶颈

AI写代码越来越快，团队真正头疼的反而是怎么审。人类Reviewer的注意力有限，通用Coding Agent又容易漏文件、报错位置漂移、把低价值建议刷屏。Open Code Review的走红，说明市场开始承认一个现实：写代码的自动化越强，审代码的工业化越急。

## 它不是让大模型自由发挥

Open Code Review最有意思的地方，是把确定性工程和Agent能力分开。文件选择、变更分组、规则匹配、定位校正这些必须稳定的步骤，由流水线硬约束；需要动态读上下文、搜索代码库、理解变更意图的部分，再交给LLM Agent。这样做的目标不是让AI更会“聊天式评审”，而是让它少漏、少飘、少乱说。

## 低噪声比全覆盖更值钱

代码审查里，召回率当然重要，但如果一个Bot每天报一堆无关紧要的问题，人很快就会静音它。Open Code Review选择更偏向precision，牺牲一部分覆盖，换来更少噪声和更低token成本。对工程团队来说，这个取舍很现实：Reviewer注意力才是最贵的资源。

## AI代码工具会先把流程拆开

很多人把AI编程想象成一个全能程序员，从需求到上线一条龙。但真实工程更可能被拆成多个专业环节：生成、测试、审查、安全扫描、性能回归、发布。Open Code Review代表的是其中一个很具体但很刚需的环节：让AI先把明显风险筛出来，把人类留给架构判断和高价值取舍。

## 最后一句

Open Code Review提醒我们，AI编程革命不是只有“谁更会写代码”。当机器开始大量产出代码，谁能把审查做得稳定、低噪、可追责，谁就抓住了下一阶段的软件工程入口。
