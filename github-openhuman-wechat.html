OpenHuman 凭什么击败 OpenClaw 和 Hermes？

GitHub Trending 榜单变天了。

一个名叫 OpenHuman 的项目，两周内冲到全球趋势榜榜首，力压占据榜单数月的 OpenClaw 和 Hermes。更让人惊讶的是，它的核心理念和目前主流的 AI Agent 架构完全相反。

主流 Agent 的思路是：先处理任务，再考虑上下文。

OpenHuman 的思路是：先建立上下文，再处理任务。

听起来像是玩概念？看完它的架构设计，你可能会改变想法。

● ● ●

01 Context-First：第一天就建 Memory Tree

传统 Agent 的问题是什么？上下文丢失。

你让 Agent 做一个复杂任务，它执行到一半，发现需要之前的某个信息，但上下文窗口已经滚过去了。于是它要么瞎猜，要么重新问你。

OpenHuman 的解决方案是：从第一个交互开始，就构建一棵 Memory Tree（记忆树）。

Memory Tree 的核心设计：

• 每个对话、每个文件、每个操作结果，都会被压缩成一个节点

• 节点之间有显式的依赖关系（谁引用了谁、谁覆盖了谁）

• 每次任务执行前，先从 Memory Tree 中检索相关上下文

• 上下文检索是语义级别的，不是简单的关键词匹配

听起来像是 RAG？不完全是。RAG 是"检索-增强-生成"，重点在增强。OpenHuman 是"记忆-理解-执行"，重点在理解。

项目作者的原话："我们不是在做更好的 RAG，我们是在做一个有记忆的 Agent。区别在于：RAG 是被动的，Memory Tree 是主动的。"

02 为什么能击败 OpenClaw 和 Hermes？

先说一下被超越的两个项目：

OpenClaw：37万 Star 的顶流项目，主打"终端+浏览器+文件系统"三位一体的 Agent 体验。优势是生态完善、插件丰富。

Hermes：主打多 Agent 协作，能让多个 Agent 分工合作完成复杂任务。优势是任务编排能力强。

OpenHuman 击败它们的原因，归结起来就一点：长链任务的成功率更高。

社区的实测数据（非官方）：

• 10 步以内的任务：三者成功率差不多，都在 85% 以上

• 20-30 步的任务：OpenClaw 约 60%，Hermes 约 55%，OpenHuman 约 78%

• 50 步以上的任务：OpenClaw 约 30%，Hermes 约 25%，OpenHuman 约 52%

这个差距在复杂项目中会被放大。比如"帮我重构这个项目的测试框架"这种任务，可能涉及 100 多个步骤，中间要记住无数的依赖关系和约定。OpenHuman 的 Memory Tree 让它在这种场景下明显更可靠。

03 但与此同时，一场安全风暴正在发酵

就在 OpenHuman 登顶的同一周，另一个爆炸性消息震动了整个 Agent 社区：

安全公司披露了一个名为 "Claw Chain" 的漏洞链，影响包括 OpenClaw 在内的多个主流 Agent 框架。

⚠️ Claw Chain 漏洞链概述：

Step 1：通过特定的 prompt 注入绕过沙箱

Step 2：利用插件系统的权限漏洞提权

Step 3：伪造 Owner 权限，实现持久化控制

简单来说：一个恶意的 prompt 可能让你的 AI 助手变成别人的后门。

OpenClaw 官方在 48 小时内发布了紧急修复，但这件事引发的讨论远未结束：当 Agent 获得越来越多的系统权限，我们真的准备好了吗？

一位安全研究员的警告："我们正在给 AI 越来越多的钥匙——文件系统、终端、浏览器、API。但 AI 的行为是不可预测的。一个聪明的攻击者只需要找到一个入口。"

04 Agent 的下一个战场：安全 vs 能力

OpenHuman 的崛起和 Claw Chain 漏洞，其实揭示了同一个趋势：AI Agent 正在进入"深水区"。

浅水区的竞争是功能数量：谁支持的工具多、谁的插件生态好。

深水区的竞争是核心能力：

1. 长链任务的可靠性

能不能在 100 步的任务中保持一致性？OpenHuman 的 Memory Tree 是一个方向。

2. 安全边界的清晰性

能不能在给 Agent 权限的同时，确保它不会被劫持？Claw Chain 是一个警钟。

3. 可解释性和可审计性

Agent 做了什么决定、为什么做这个决定、能不能回溯？这在企业场景中是刚需。

对于开发者来说，我的建议是：

先关注 OpenHuman，学习它的架构思想；同时盯紧 Claw Chain 的后续进展，安全补丁一定要打。

Agent 的战争才刚刚开始。
