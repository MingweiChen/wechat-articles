01 为什么这件事很难？

GPU 底层算子（Kernel）开发是大模型训练的"隐形门槛"。

写一个 Triton 或 CUDA kernel，你需要同时精通：数值计算的数学原理、GPU 硬件架构、内存管理与寄存器优化、还要能在精度和性能之间反复权衡。全球真正能胜任这个活的人，可能不到几千人。

更要命的是：这批人要同时服务于整个开源社区。每发布一个新的大模型架构（比如 Llama 4、Gemma 3），就需要有人手动适配优化。PyTorch 团队忙不过来，Hugging Face 团队忙不过来，连 NVIDIA 自己都忙不过来。

02 领英的解法：让 AI 自己写 Kernel

领英 AI 基础设施团队构建了一套完整的 Agent 工作流，覆盖算子开发的全生命周期：

🔧 liger-kernel-dev：从零创建新算子

输入可以是 PyTorch 代码片段、论文链接、甚至一句自然语言描述——比如"ReLU 平方激活函数"。

Agent 工作流：
• 理解阶段：分析输入，将算子分类为三种复杂度等级
• 执行阶段：参考同类型 Liger kernel，生成完整实现、测试、基准
• 验证阶段：运行正确性校验，硬性错误阻断，软性偏差标记复核

实际成果（PR #1171）：ReLU² kernel 实现 1.9 倍前向加速、3.2 倍反向加速、37.5% 内存节省。过去需要专家花几天完成的工作，现在只需要人类审核一份结构化 profile 文档。

🔗 liger-autopatch：适配新模型架构

每个大模型都有微妙的架构差异：Gemma 会把部分计算上转到 fp32，Llama 只做部分转换；RMSNorm 的 offset 参数各家不同；MoE 路由、视觉编码器、RoPE 变体更是五花八门。

错误处理任何一个细节，你不会收到报错——只会得到一个"看起来在训练，其实在产生垃圾梯度"的模型。

实际成果（PR #1165/1166）：Nemotron 和 Ministral 两个模型的适配，代码直接合并，人工只做 profile 审核。

⚡ liger-kernel-perf：优化现有算子

这是最硬核的部分。Agent 会：
• 运行 NVIDIA NCU 性能分析
• 诊断瓶颈类型（内存带宽受限、计算受限、延迟受限）
• 生成多个优化版本，每个版本附带"实验室笔记"
• 自动学习历史优化经验，迭代改进
• 任何导致其他指标下降超过 5% 的改动会被自动拒绝

实际成果（PR #1187）：fused_add_rms_norm 反向传播 kernel 在 H100 上只有 12.5% 的 GPU 利用率——115 个寄存器/线程导致严重的寄存器压力。Agent 诊断问题后应用四项针对性优化。

最终结果：3.35 倍反向加速，整体 59% 全程加速，40 项测试零回归。

03 内部实战：64.7% GPU 成本直降

领英把这套系统用在了内部推荐模型的训练上。

他们构建了一个基于 torch.compile 的 kernel 选择框架：通过 TorchDynamo 捕获计算图，识别可融合操作，从 CI/CD 验证过的 kernel 注册表中选择最优实现，通过 torch fx 图变换自动替换。

📊 Agent 生成的批处理分区均值池化 kernel 成果：

编码器步骤时间：400ms → 40ms（10 倍提速）
平均训练步骤时间：1.12s → 0.39s（3 倍提速）
端到端训练 GPU 小时数：节省 64.7%

这不是实验室数据，是真实跑在领英推荐系统训练流程里的生产结果。

04 这套系统为什么有效？五个设计原则

领英总结的设计原则，对任何想用 Agent 做工程自动化的团队都有参考价值：

1. Profile 才是产品，代码是副产品
Agent 不直接写代码——它先生成一份结构化的"决策档案"（Profile），捕获所有架构决策。人工审核的是推理过程，不是代码 diff。

2. 复用而非发明
三级分类系统确保 Agent 参考同类已验证的实现，而不是自由发挥。创造力被约束在真正需要创造力的地方。

3. 阶段性人工检查点
三阶段流水线（理解→执行→验证）之间强制人工复核，把审核工作量控制在"看一份文档"的级别。

4. 验证是一等公民
区分硬性失败和软性失败，三次失败后停止生成并汇报，而不是产出越来越错的代码。

5. 模板驱动一致性
生成的代码遵循 Liger 项目的所有约定，让审核快速、让代码可维护。

06 对开发者意味着什么？

如果你在做 Agent 工程化：

直接抄"Profile 作为中间表示"的模式。不要让 LLM 直接从自然语言生成代码，强制它先输出结构化决策文档，人审文档，代码从文档确定性生成。

如果你在维护开源库：

发布你自己的 Agent Skills。Liger 把工作流直接放在仓库里，任何人用编程 Agent 都能跑。你的贡献者管道瞬间扩容无限倍。

如果你对 GPU kernel 开发感兴趣但被门槛劝退：

护城河刚刚矮了一大截。你现在可以通过理解数学原理——而不是硬件细节——为顶级开源项目贡献优化算子。
