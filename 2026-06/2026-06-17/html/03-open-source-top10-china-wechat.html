开源智能榜前十占八席：
中国军团登顶，八成创业公司默认选它

 

把「能力」和「自由」打包送出去的那一方，先抢到了开发者的默认选择。

打开 Artificial Analysis 的智能指数 v4.0 榜单,把所有「权重可下载」的模型单独拎出来排个序,前十名里有八个,你在中文技术社区都见过它们的名字。

Kimi K2.6 以 53.9 分坐在第一。紧随其后的是 MiniMax 的 MMo-V2.5-Pro,53.8。第三名 DeepSeek V4 Pro,综合分 51.5,而它在 Codeforces 上的编程评级冲到了 3206,这个数字越过了榜上所有模型,包括那些不开源、要按 token 收费的旗舰。再往下是 GLM-5.1 的 51.4,以及刚刚更新的 Qwen3.5。

来自美国超大规模厂商的开源模型,在这份前十名单里只剩下一个 Gemma 4。一根独苗。

这件事如果倒退十八个月讲给任何一个硅谷的人听,大概率会被当成段子。那时候大家默认的图景是:闭源吃肉,开源喝汤;最强的智能锁在 API 后面,开源永远慢半拍、差一档。可现在你去翻那些用开源模型搭产品的创业公司——据 Artificial Analysis 自己的口径,约八成跑在开源底座上的初创团队,默认选项已经是中国模型。

我想聊的不是「谁赢了」。榜单每个月都在变,名次这东西没什么好争。我更感兴趣的是另一个问题:为什么是开源这条路、把一个原本被认为落后的玩家,送到了智能的最前排?

一份榜单解决不了的事,它至少能戳破一个错觉

先说清楚榜单是什么。智能指数 v4.0 不是某一项考试,它把推理、数学、代码、知识等一堆基准压成一个综合分。你可以质疑它的加权方式,可以说某些基准已经被「应试」过度,这些质疑都成立。

但有一件事它戳得很准:「开源 = 二流」这个心理预设,已经过期了。

DeepSeek V4 那个 3206 的 Codeforces 评级是最刺眼的注脚。编程是少数几个几乎无法靠刷榜糊弄过去的能力,题目是新的,要真的写出能跑通的代码。一个开源、能下载、能本地部署的模型,在这项硬指标上压过了所有要付费调用的闭源旗舰。这不是「接近」,是「越过」。

到这一步,故事如果停在「中国模型很强」,那就成了又一篇榜单复述,没什么意思。真正值得拆的是后面那层:这种领先不是偶然撞上的,它有结构。

把三样东西摆在一起,你会看到一种「选择」

我一直觉得,看一个技术阵营强在哪,不能只看它做了什么,要看它被什么逼着做选择。

这一批中国模型身上,有三个特征反复出现,而且总是一起出现。

第一是低成本。不是「便宜一点」,是训练和推理的单位成本被压到让闭源厂商难受的程度。第二是长上下文。几十万 token 起步,有的把窗口拉到上百万。第三是许可证——清一色的 Apache 2.0 或类似的宽松条款,商用免费、可改可分发、不设门槛。

单看每一项,都不算独门绝技。可把这三样焊在一起,意味就变了。

低成本压低了「用得起」的门槛,长上下文把「能干的活」从聊天扩到了整本文档、整个代码库,Apache 2.0 则把「随便拿去改」这件事从灰色地带变成白纸黑字的权利。一个开发者拿到这样的组合,他不需要谈商务、不需要等额度、不需要担心明天涨价或者关停。下载、部署、上线,链路里没有一道收费闸门。

这里有个微妙的点。这三样东西,没有一样是闭源最强模型愿意全给你的。闭源的商业模式天然要求你为最好的智能持续付费,所以它给得起能力,但给不起「白送的所有权」。开源这条路恰恰相反:它在单点能力上未必每次都登顶,但它把「能力 + 成本 + 自由」这一整包,毫无保留地塞进了你手里。

那八成创业公司默认选中国模型,选的根本不是某个跑分。他们选的是这一整包确定性。

为什么是「开源」先到这里,而不是「闭源」

顺着这条线往下推,会碰到一个更有意思的问题:同样是做大模型,为什么把智能推到开源前排的,是这一批玩家?

我的判断是,这背后是一道很现实的约束题。当顶级算力的获取变得不那么顺畅,当「无限堆卡、无限烧钱」这条路走起来有摩擦,一个团队会被逼着回答:有限资源下,怎么把价值做到最大?

闭源那条路的答案是把最好的东西攥紧,靠 API 收租,用收入再去换更多算力,滚雪球。这条路在资源充裕时极其顺。但它有个隐含前提,你得一直供得上、烧得起。

开源给出了另一个答案:既然单靠自己滚不动,那就把模型放出去,让整个生态替我滚。你开源一个强模型,全世界的开发者帮你找 bug、写工具链、做微调、铺生态位。Apache 2.0 是这套打法的法律地基,长上下文和低成本是诱饵,而那八成默认选你的创业公司,就是滚起来的雪球本身。

说到这我想起一段更老的历史。上世纪九十年代,有人靠把操作系统的源码摊开在所有人面前,硬生生在巨头脚下长出了一整片生态,最后那套开放系统成了今天云和服务器的地基。当年也没什么人预料到一个「免费、谁都能改」的东西,能跑赢那些资金、人力、渠道都碾压它的商业产品。

历史不会重复,但它押韵。开放系统赢过封闭系统的故事,在软件世界里已经上演过不止一次。每一次的剧本都差不多:封闭方靠资源和先发优势领跑,开放方靠生态的复利和「人人可参与」的势能,在一个谁都没料到的时间点完成反超。

别急着喊「开源赢了」,这只是上半场

写到这,如果我直接下个「开源终将碾压闭源」的结论,那也是在偷懒。

闭源没有出局。在最前沿那一小撮、不计成本要榨干每一分性能的场景里,闭源旗舰依然有它的位置;在需要极致一致性、极致安全兜底、极致服务保障的地方,「有一家公司对结果负责」本身就是产品的一部分。开源给你自由,但自由的另一面是:出了问题,没人替你扛。

更老实地说,今天这份榜单上的领先,是「此刻」的快照。下个月闭源放一个大招、把综合分重新拉开,完全可能。名次会反复横跳,这恰恰说明双方都还在牌桌上。

但有一样东西,我认为是回不去了。「最强的智能只能锁在 API 后面」——这个让闭源吃了好几年红利的隐含前提,被这份榜单亲手拆掉了。一旦开发者验证过「白送的开源模型也能打到第一梯队」,他们对闭源的付费意愿、议价心态、技术依赖,都会被永久地重新校准。这种心理预期的迁移,比任何一次跑分领先都更难逆转。

开源和闭源的长期博弈,本质从来不是哪个模型分更高。它是两种关于「智能该如何分配」的世界观在掰手腕:一边主张最好的东西应该有人定价、有人负责、有人持续投入;另一边主张最好的东西应该被摊开、被复制、被任何人无成本地拿走。

这一局,把「能力」和「自由」打包送出去的那一方,先抢到了开发者的默认选择。前十里那八个名字,不过是这个选择被量化之后的样子。

牌还在发。但有些桌上的规矩,已经悄悄改了。
