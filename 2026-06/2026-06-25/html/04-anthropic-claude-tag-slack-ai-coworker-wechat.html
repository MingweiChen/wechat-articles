Claude被塞进群聊当同事
变的不是能力，是它站的位置

 

6月23日Anthropic上线Claude Tag，把Claude装进Slack群聊，你@它就能派活。看似普通的集成更新，真正挪动的是它从「私聊工具」变成了「群里同事」。

负责 Claude Code 的产品负责人 Cat Wu，在介绍这次新东西时说了一句很反直觉的话。

大意是：这些能力，其实大多早就存在了。真正强的，是你能像 @一个同事那样 @它 这个「形态」本身。

这话值得停下来咂摸一下。一家公司发新功能，通常急着告诉你「我又能干什么了」。她偏不，她说能干的活没怎么变，变的是它出现在你工作里的方式。

6 月 23 日，Anthropic 上线了 Claude Tag。一句话讲它是什么：把 Claude 直接装进 Slack 的群聊，你在频道里 @Claude 就能派活，它干完会主动回到那条 thread 里戳你。

听上去像个再普通不过的集成更新。但如果你顺着 Cat Wu 那句话往下想，会发现这次真正挪动的，不是 Claude 的能力边界，而是它的存在形态：从一个你私聊的工具，变成了一个待在群里的同事。

这两件事，常被混为一谈。今天就把它们掰开。

官方产品截图：在 Slack #launch 频道里 @Claude 派活，它接活、回到 thread 里贴出做完的清单——这就是这次真正变了的「形态」

先把「能力升级」和「形态升级」分清楚

Anthropic 官方截图：同事在 #checkout-incidents 频道 @Claude 查故障，Claude 当众接活、列出排查步骤——群聊里直接派任务的真实形态

过去一年，几乎每一次 AI 的大新闻，讲的都是能力：参数更大、跑分更高、上下文更长、又会调工具了。这是一条所有人都看得懂的尺子，谁的分高，谁就领先。

Claude Tag 这次，几乎没有在这条尺子上加刻度。

@Claude 派活、它拆解任务、调用被授权的工具、把结果贴回来，这些动作，在它之前的 Slack 集成、在 Claude Code 里，大体都做得到。Anthropic 自己也没藏着掖着，官方说法就是这是「已有若干集成的一次演进」。

那它到底新在哪？新在四个字：怎么待着。

以前你跟 AI 的关系，是一对一私聊：你打开一个框，问一句，它答一句，关掉，这段对话基本就死了。Claude Tag 把这个关系，搬到了群里。

Slack 的负责人 Rob Seaman 给了一个特别精准的说法，他说这是「让 AI 变成多人游戏」：以前是私下的一来一回，现在 Claude 是当着所有人的面出现的。

「私聊」和「群聊」，听起来只是个场景差别。但对一个 AI 来说，这一步跨过去，它的角色就彻底变了。

同事和工具，差在哪三件事

四个维度看「工具 vs 同事」：在哪、归谁、怎么动、记不记事，Claude Tag 都换了位置

把 AI 从工具变成同事，不是换个皮肤。一个真正的「同事」，至少得满足三件工具做不到的事。Claude Tag 这次，恰好是冲着这三件去的。

第一，它是共享的，不是你私人的。 一个频道里只有一个 Claude 身份，所有人共用。这意味着什么？意味着同事 A 昨天交代给它的事、它做到一半的活，同事 B 今天进来能直接接着往下推，因为大家看到的是同一个 Claude、同一段上下文。这跟你电脑里那个只属于你、关掉就清零的私聊框，是两个物种。

第二，它会主动，不是只会被动应答。 Claude Tag 有一个叫 ambient（环境）的模式：它不等你问，自己盯着频道，该提醒就冒出来提醒、把组织里别处的相关动静拎过来、还会回头追那些被大家忘掉的 thread。工具是你按一下它动一下；同事是你没盯着的时候，它还在帮你盯着。

第三，它跨时间记得事。 它会持续跟着频道走，越跟越懂这摊活；在被授权的前提下，还能自动从组织别的地方搜集事实。换句话讲，你不用每次都把背景重讲一遍，这正是「同事」和「客服机器人」最大的体感差别。

下面这张表，大概能说清这次到底挪了什么：

维度 过去的 AI 工具 Claude Tag
在哪 你私人的对话框 群聊频道里
归谁 你一个人 整个频道共享
怎么动 你问它才答 主动盯、主动提醒
记不记事 关掉就清零 跨时间记上下文

Cat Wu 自己举了个用法，挺能说明问题：她给自己的 Claude Tag 开了读 Gmail 的权限，它读她的邮件，一旦有重要的人来信，就跑到 Slack 上戳她，因为她在 Slack 上回得更勤。你看，这里 Claude 干的活（读邮件、提醒），技术上一点不新鲜；新鲜的是它把自己嵌进了她真实的工作动线里。

这事难复制的地方，不在技术，在「社会性」

到这里，真正有意思的问题才浮出来：既然能力不是新的，那对手照着做一个，不就行了？

这里有个微妙的点。

如果护城河是能力，比如更高的跑分、更强的推理，那它是技术性的。技术性的领先，本质上都有保质期，别家砸钱、堆人、过几个月追上来，是常态。这两年我们看了太多这种你追我赶。

但「同事」这个形态带来的黏性，不是技术性的，是社会性的。

一个工具难不难换，看的是迁移几个 API、导出几份数据。一个同事难不难换，看的是它已经多深地长进了团队的协作流程里。

你品一下：当一个频道里所有人的工作交接，都默认经过这个 Claude；当半截的活、忘掉的 thread，都靠它续上；当新来的同事第一件事是去看「Claude 之前做到哪了」，这时候你想把它换掉，要动的就不是一个软件，而是整个团队已经形成的协作习惯。

Anthropic 给了一个内部数字，佐证这种「长进去」有多深：在它自己内部，Claude Tag 现在已经贡献了产品团队 65% 以上的代码生成，而且正从工程蔓延到客服、分析、运营。它不是被当成一个偶尔用一下的工具，而是真的当成了流程里的一环。

刚加入 Anthropic、负责预训练的 Andrej Karpathy，把这层意思说得更直白。他说这是与 Claude 交互的一种新范式：一旦你把底下那些脏活累活（工具、集成、计算环境、记忆、安全）全部打通，让它「就是能用」，Claude 基本上就无缝加入了团队，你可以像跟人说话一样跟它说话，它能帮你扛各种各样的活。

注意他强调的不是模型多聪明，而是「底层打通后无缝加入团队」。这恰恰是形态升级、而非能力升级的注脚。

当然，它也给自己埋了三道坎

抢「组织上下文」这条赛道已挤满人：Anthropic、微软 Graph、Snowflake/Databricks、Glean

把 AI 推到「同事」这个位置，风口和风险是同一件事的两面。

一是权限边界。 一个待在群里、能主动读东西的 AI，管不好就是数据泄露的口子。Anthropic 的解法是把控制权收到管理员手里：只有组织的 Owner 能给 Claude 配身份、连工具、定它能进哪些频道、设花费上限、查活动日志。而且每个 Claude 身份被严格圈定在指定频道里，一个为法务配的 Claude，不能把记忆窜到工程频道去。这套围栏立得越严，恰恰说明「主动＋共享＋有记忆」这套形态本身，风险有多大。

二是它远不是 Anthropic 一家在抢的位置。 把「组织上下文」喂给 AI 这件事，微软有 Graph，通过 Copilot 和 Work IQ 来做；Snowflake、Databricks 在把自己摆成存放组织隐性知识的后端；Glean 干脆专做那层夹在模型和企业数据之间的「理解层」。换句话说，「让 AI 长进公司肌理里」这条路，已经挤满了人。Claude Tag 跑得早，但不孤独。

三是它还在很早的阶段。 目前只对 Claude 的 Team 和 Enterprise 客户开放 beta，底座是上个月才发的 Opus 4.8，老版「Claude in Slack」体验要到 8 月 3 日才迁移过来。一个刚上线、还在 beta 的东西，能不能真稳定地扛住一个团队的日常协作，得用时间换答案。

写在最后

回到 Cat Wu 那句话：能力大多早有，变的是「能像 @同事一样 @它」这个形态。

这句话之所以值得当成本篇的题眼，是因为它点破了一个我们常犯的误读：总盯着 AI 又强了多少，却没注意它正悄悄换一个位置待着。

能力的领先，是技术账，可以用钱和时间追平。形态的领先，是社会账，追的是一整套已经长进流程里的协作习惯，这玩意儿砸钱买不来，得一条 Slack 消息、一条 Slack 消息地慢慢长。

所以，Claude Tag 真正想干的，不是再赢一个跑分。是趁着别人还在比谁更聪明的时候，先一步把自己，变成你删不掉的那个同事。
