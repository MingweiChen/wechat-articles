AI 编程工具

8 个 AI 同时给你写代码
Cursor 3 上线那一周，硅谷程序员的钱包先哭了

Cursor 3 让 8 个 Agent 并行干活、Claude Code 占据企业半壁江山、GitHub 改成按 token 计费。72 小时之内，「写代码」这件事被三家公司同时改了一次定义。

4 月 2 日 Cursor 3 上线。codename 叫 Glass。

我那一周用它写了一个内部小工具，跑完发现自己问了一个奇怪的问题：我到底是在写代码，还是在调度一支临时雇佣军？

接下来这一周，硅谷不止一家公司在问同样的事。Anthropic 的 Claude Code 已经吃下了 Menlo Ventures 那份调研报告里 54% 的 coding agent 用户份额，Cursor 在 Fortune 500 占到 64%，两条路线第一次正面对撞。Warp 5 月把整个终端开源、拿了 OpenAI 投资，GitHub 6 月把 Copilot 改成按 token 计费。72 小时之内，编程这件事被三家公司同时改了一次定义。

下面这些问题，是我那一周被同事追着问、被自己的 GitHub 账单追着问的几个。

Q1：Cursor 3 到底干了啥？

最大变化只有一个词：并行。

Cursor 3 把原来"一个 Agent 帮你做一件事"改成了"8 个 Agent 同时帮你做 8 件事"。背后机制不复杂，就是 Git worktrees：同一个仓库开出 8 份独立工作目录，每个 Agent 各拿一份，互不打扰，做完再合回来。

Glass 这个 codename 其实有点暗示。它把代码库变成一块半透明的玻璃：你能看到 8 个分身在各自那一格里跑，但他们彼此看不到对方。冲突留到合并时再说。

Composer 2 是这一代的内核引擎，Anysphere 自家训的。但发布两周后，被开发者扒出训练里大概率 fork 了 Kimi 2.5 的部分权重。Anysphere 没有正面回应，社区争论一波就过去了。这件事比技术更值得记一笔，因为它解释了为什么过去三个月 ARR 能从 10 亿翻到 20 亿：他们不再死磕自研，谁的模型好就缝谁的。

钱方面，Anysphere 累计融到 30 亿美元，估值 293 亿。一家做编辑器的公司估值快赶上甲骨文一年自由现金流了，听起来荒唐，但 Fortune 500 里 64% 在用，这数字本身就是答案。

Q2：跟 Claude Code 比，到底哪不同？

这是过去一周最被低估的对比。

Claude Code 走的是另一条路：纯命令行，没有 IDE，跑在你的终端里。Anthropic 自己是 Claude Code 的最大客户，他们的工程师就用它写自己的下一代模型代码。这条路线的潜台词是"模型即产品"，编辑器只是壳。

Cursor 走相反方向：IDE 就是主战场，模型可以随便换。今天用 Composer 2，明天 Claude 4.5 出了就接，后天 Gemini 3 出了再接。它把自己定位成"AI 时代的 VS Code"，赌的是 IDE 这层入口比模型更值钱。

Menlo Ventures 那份调研里有个反直觉的数字：Claude Code 用户份额 54%，但月活用户里有相当比例是 Anthropic 自家工程师 + 早期 power user。Cursor 那边份额低一些，但用户结构是金字塔形状，有学生有创业团队也有 F500 里几万人规模的团队部署。

我那周做了一个不太严谨的对比：让两边写同一个数据库 migration 脚本。Claude Code 给的代码更干净，单文件能跑，几乎不需要改。Cursor 给的代码更"工程化"，会顺手把测试、文档、CI 配置都补上，但偶尔过度设计，加了我没要的东西。

这两条路其实在赌不同的未来。Anthropic 赌"模型够强了就不需要 IDE"，Cursor 赌"模型再强也得有人给你管理 8 个分身"。我个人偏向后者，但理由不是技术，是组织。大公司里没人愿意 ssh 进生产服务器跑 Claude Code，但每个工程师都已经装了 VS Code 那一套。

Q3：那 Warp 开源、Copilot 改计费又是什么操作？

5 月 Warp 把整个终端开源，同时拿了 OpenAI 一笔投资。这个组合很微妙：开源是为了让所有 AI 公司的 Agent 都能跑在 Warp 上，OpenAI 投资是为了确保自家 Agent 跑得最顺。Warp 不再做终端，它在做 Agent 操作系统。

GitHub Copilot 6 月把订阅制改成 token billing。原来 10 美元一个月随便用，现在按你烧掉多少 token 算。微软给的官方理由是"AI 推理成本不可持续"，私下版本是：重度用户烧的 token 已经远远超过 10 美元，亏本买卖做不下去。

这两件事拼在一起，再加上 Cursor 3 的并行 Agent，会发现它们在共同指向一个事实：Agent 这东西不是 SaaS 商业模型能装下的。SaaS 卖的是"无限使用"的承诺，但 Agent 每跑一次就在真金白银烧 GPU。订阅制只能是过渡，按用量计费才是终局。

GitHub 是头部玩家，它转得最早——这可能是给整个赛道的预告。

Q4：8 个 Agent 并行真有人用吗？花多少钱？

我那一周看到的最离谱一条 Twitter：有个独立开发者用 Cursor 3 + 8 个并行 Agent，两天烧了 2000 美元 API 费用。

他的工作流是这样的：早上把今天要做的 8 个 issue 复制到 Cursor，让 8 个 Agent 同时启动；中午吃饭回来 review、合并、再分配下一批；晚上睡觉前再丢一批跑通宵。听起来像在管一个 8 人团队，区别是这个团队不睡觉、不喝咖啡、也不跟你扯闲。

但 2000 美元两天意味着什么？折算下来差不多是一个初级工程师在硅谷的月薪。他不是在省人，他在用钱换时间。这跟传统外包还不一样：外包至少有人跟你确认需求，Agent 是字面意义的黑盒加 24 小时服务。

我自己那周没烧到这个量级，大概 80 美元，写了一个内部仪表盘的全部 CRUD 加测试。换算成时间大概是我自己写的 1/3，质量比我手写的差一点点（有几个 edge case 没覆盖到），但 review + 修一遍之后能用。

这里有个我看下来比较反直觉的点：真正烧钱的不是模型贵，是并行。8 个 Agent 同时跑就是 8 倍 token，加上 worktrees 之间的上下文同步，实际花费经常是单 Agent 的 12-15 倍。所以 Cursor 给你 8 个并发不是慷慨，是把成本完整透明给你看。

至于 Composer 2 fork Kimi 2.5 那个风波，对终端用户其实影响不大。模型好坏不重要，重要的是这件事说明了一个事实：编程模型已经接近商品化，区别只在于谁的产品包装得更好用。Cursor 那一周该用的人没有少。

Q5：那程序员的工作方式真的变了吗？

我倾向于说：不是被取代，是被劈开了。

劈成两半。一半是"调度型程序员"，他们的工作开始变成定义任务、拆分 issue、给 Agent 写明确的 prompt、review 输出、合并代码。这些人在变多，产出率正在上升 3-5 倍，但 review 这件事会慢慢成为新的瓶颈。Cursor 3 的 8 个并行让这一点暴露得很明显：你能开 8 个 Agent，但你 review 不过来。

另一半是"写代码型程序员"，核心系统、性能瓶颈、安全相关、新算法。这些场景里 AI 还做不了主，需要工程师真的坐下来想清楚。这部分工作不会消失，反而因为前一半被自动化了，议价能力可能在上升。

中间被挤压的是"中等难度、可以拆得很细、模式相对固定"的那一类工作。CRUD、表单、配置、日常 bug 修复——这些以前占一个工程师 60% 的时间，现在被 Agent 接走了大半。

我不太同意"程序员要失业"那种叙事。我看到的更像是分工重组：未来一两年内，"会用 Agent" 会变成跟"会用 Git" 一样基础的技能。不会用就跟现在不会写 SQL 一样，找工作很难；但会用了也只是入门，真正拉开差距的还是工程能力本身。

至于"两天烧 2000 美元"那位老哥，他在 Twitter 上后来加了一条：钱是公司报销的，他是某个 YC 公司的创始工程师。这条信息很关键。Agent 大爆发的真正受益者不是大厂员工，是预算少、需要单兵作战的早期团队。

写代码这件事，未来可能不再是写。是讲清楚你想要什么。
