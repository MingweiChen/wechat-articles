开源安全观察

curl 关闭 7 年赏金计划
AI 垃圾报告正在拖垮整个开源社区

四大事件揭示开源生态的信任危机

87 个漏洞，10 万美元奖金，7 年心血——curl 赏金计划宣布终结。

这不是一个普通项目的落幕，而是整个开源安全生态遭遇系统性冲击的缩影。当 AI 生成的垃圾报告淹没维护者邮箱，当 MCP 协议的设计缺陷波及 7000+ 服务器，当 600 万假 Star 操纵 GitHub 信任体系，开源世界正在经历一场前所未有的信任危机。

本期，我们深度解读四个正在重塑开源格局的重大事件。

● ● ●

01 curl 赏金计划：被 AI slop 逼停的 7 年传奇

2026 年 1 月 31 日，curl 创始人 Daniel Stenberg 宣布正式关闭运行了近 7 年的漏洞赏金计划。这个嵌入在 Windows、macOS 和几乎所有 Linux 发行版中的网络传输工具，其安全研究曾是行业标杆。

📊 历史成绩单

• 确认漏洞：87 个
• 累计奖金：超 10 万美元
• 合作平台：HackerOne + Internet Bug Bounty

转折点发生在 2024 年下半年。AI 生成的低质量报告（业内称为"AI slop"）开始大规模涌入。到 2025 年，漏洞确认率从此前的 15% 以上暴跌至不足 5%——每 20 份报告里只有不到 1 份是真实的安全问题。

"我们正在被 DDoS 攻击。这些垃圾报告对维护者的心理造成了严重负担，消耗了本该用于真正改进项目的时间和精力。"

—— Daniel Stenberg

HackerOne 的数据显示，curl 项目遭受的垃圾报告远超同类开源项目。Stenberg 表示，这些"安全研究者"往往带着恶意目的，极力将无关紧要的发现包装成"严重漏洞"，却从不参与实际的代码修复。

新规则很简单：不再提供任何金钱奖励，提交垃圾报告者将被永久封禁并公开点名。这是开源世界对 AI 滥用的一次强硬回击。

● ● ●

02 MCP 协议安全危机：7000+ 服务器暴露在 RCE 风险下

2026 年 4 月，OX Security 研究人员披露了一个令人震惊的发现：Anthropic 的 Model Context Protocol（MCP）存在"设计层面"的远程代码执行漏洞，影响范围覆盖 Python、TypeScript、Java、Rust 全部官方 SDK。

⚠️ 影响规模

• 受影响服务器：7,000+
• 受影响下载量：1.5 亿+
• 涉及项目：LiteLLM、LangChain、LangFlow、Flowise 等

问题的核心在于 MCP 的 STDIO 传输接口设计：它会在返回错误之前先执行任意操作系统命令。这意味着攻击者可以在任何运行 MCP 的系统上获得完全控制权，访问敏感数据、API 密钥、聊天记录，甚至进行横向移动。

研究人员发现了 10 个相关 CVE，涵盖 GPT Researcher、LiteLLM、Agent Zero、Windsurf 等热门项目。更令人担忧的是，Anthropic 官方将这一行为定性为"预期功能"，拒绝修改协议架构。

"这是 AI 供应链漏洞之母。一个架构决策，悄无声息地传播到每种语言、每个下游库、每个信任该协议的项目中。"

—— OX Security 研究团队

紧急建议：立即审计所有 MCP 集成，阻止公网 IP 访问 STDIO 接口，在沙箱中运行 MCP 服务，仅从可信来源安装 MCP 服务器。

03 TalkPipe：桑迪亚国家实验室的 Unix 管道式 AI 编排

在一片安全阴云中，一个来自桑迪亚国家实验室的开源项目带来了一丝清新。TalkPipe 是一个 Python 工具包，它的设计哲学简单而优雅：像 Unix 管道一样编排 AI 工作流。

🔧 核心特性

• 双重 API：Python 管道语法 + ChatterLang DSL
• 流式生成器：内存友好的大数据处理
• 即插即用：支持 OpenAI、Ollama、Anthropic

TalkPipe 的独特之处在于它不试图成为一个庞大的 AI 平台，而是专注于做好一件事：让 AI 管道像 Unix 命令一样可组合、可脚本化、可审查。

用 Python 写：io.echo(data="hello") | uppercase() | io.Print()

用 ChatterLang 写：INPUT FROM echo[data="1,2,3"] | cast[cast_type="int"] | print

对于需要 RAG、批量评分、网页抓取、自动化的工程师和研究人员，TalkPipe 提供了一个不需要放弃 Python 控制权的选择。它在 PyPI 已发布到 0.12.0 版本，正在积极开发中。

● ● ●

04 600 万假 Star：GitHub 信任体系正在崩塌

这是本周最具冲击力的研究。来自卡内基梅隆大学的团队开发了 StarScout 工具，分析了 2019-2024 年间 GitHub 的 63.9 亿事件、3.26 亿 Star，发现了一个惊人的地下经济。

🚨 研究发现（ICSE 2026 收录）

• 假 Star 总量：600 万+
• 涉及仓库：18,617 个
• 参与账号：30.1 万个
• 最大非恶意类别：AI/LLM 项目

假 Star 的价格低得离谱：每个仅需 0.03 到 0.85 美元，可以在 Fiverr、Telegram 甚至普通网站上公开购买。而 VC 们普遍使用 Star 数作为项目筛选指标——Redpoint 数据显示，种子轮项目的中位数 Star 数为 2,850。

研究揭示了明显的异常模式：某个"FreeDomain"项目有 15.7 万 Star，但只有 168 个 Watcher；另一个曾登顶 Runa Capital ROSS 指数榜首的项目，被检测出 47.4% 的欺诈率。

更严重的是，假 Star 已成为恶意软件分发的温床。研究者发现的一个案例：一个有 111 个 Star（109 个是假的）的仓库，表面看是区块链应用，实际上通过混淆代码窃取加密货币。

FTC 2024 年规则已将购买虚假社交影响力列为违规行为，每次违规罚款最高 53,088 美元。SEC 也已对在融资中虚增指标的创始人提起诉讼。Star 指标作为技术尽调工具，实际上已经失效。

● ● ●

结语：开源信任重建之路

这四个事件共同指向一个核心问题：开源生态的信任机制正在被系统性地侵蚀。AI 放大了攻击者的能力，却没有同等放大防御者的资源。

curl 的决定或许会引发连锁反应——更多项目可能跟进关闭赏金计划。MCP 的案例警示我们，"设计如此"不能成为推卸责任的借口。而 GitHub Star 经济的崩塌，则需要平台、投资者和监管者共同行动。

好消息是，像 TalkPipe 这样的项目证明，优秀的开源工具仍在不断涌现。开源精神并未消亡，只是需要新的信任基础设施。
